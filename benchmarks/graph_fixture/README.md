# Express 固定版本依赖基准草稿

2026-11-18 核实。此目录包含 27 条公开 npm 版本元数据、67 条人工选定范围内的精确版本依赖边和 30 条初步质量题。材料可用于开发与真实 OpenViking 接入准备；尚未经独立标注和真实系统运行，**不能当成完整依赖树或正式验收结果**。

- [用户版](PLAN-FOR-YOU.md) · [AI 版](PLAN-FOR-AI.md)
- `docs.jsonl`：每行 `_id,title,text,source_url,metadata`；`sources/` 是 npm registry JSON 的精简快照，保留声明、许可、来源响应的 SHA-256 和源码 gitHead；每份快照本身的 SHA-256 记录于文档 metadata。快照不含完整 README、源码或个人邮箱。
- `edges.jsonl`：`source`、`target` 是 `package@version`，`locator` 是 npm 元数据 JSON Pointer。边仅来自 `dependencies` 中固定的完整版本，且目标必须在本数据集。每条边的 `evidence_id` 对应源文档。
- `questions.jsonl`：12 道跨文档路径题、6 道版本比较题、6 道单文档题、6 道否定或歧义题。金标根据来源手工选择路径再经脚本检查，并非盲标。多文档题允许其他有效路径，评估器不能只认一个最短路径。
- `build.py` 从已保存快照确定性生成数据；`validate.py` 做离线一致性核验。`python3 build.py --fetch` 会访问 npm registry 并替换快照，因此会改变冻结数据；正式实验前应保留现有版本和哈希，必要时作为新版本发布。

## 范围与时间

版本之间的差异由各自的版本元数据直接支持：例如 Express 4.18.2 指定 body-parser 1.20.1，而 4.19.2 指定 1.20.2；这两个 body-parser 分别指定 raw-body 2.5.1 和 2.5.2。这里的“历史”只表示已发布版本比较，不表示任意日期的生效区间；没有收集发布时间或废弃时间，日期有效性未知。

依赖中含版本范围（如 `~1.0.5`），实际解析依赖安装环境、注册表和锁文件。本数据未解决这些范围，也只选择了部分固定版本目标，缺失的边不代表源项目没有相应依赖。因此图的 `coverage_complete` 必须为 false；在真实系统上不能声称返回了完整依赖闭包。不得把未来版本向前套入旧版本或凭此数据推断部署状态。首批 12 题只要求一条路径，不是规格要求的完整闭包正式验收集；扩充完整子集、建立可独立复核的金标及冻结正式试题后才能用于正式门槛。
