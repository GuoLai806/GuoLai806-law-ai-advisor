# 民法典高精度 OCR + OpenViking 结构化检索 + Timely RAG 方案

结论：这条技术路线可做，但“时间维度评分”必须是法律版本有效性校验和重排，不能只按文档新旧程度打分。建议一期直接搭一条真实时间线，用事件发生日选择当时有效的法条；2020 原版先跑通，后续修订版本沿用同一数据契约接入。缺少有效期证据的资料，不能冒充当时有效。

## 目前项目实际情况

| 项目 | 已核实事实 | 对方案的影响 |
|---|---|---|
| 民法典 PDF | 64 页；有原生文字层；当前无需 OCR 也能抽出 1,260 条 | PaddleOCR 需要作为独立回退与交叉校验链路，不能把原生 PDF 文本当作 OCR 成果 |
| 现有清理 | 目录重复、条号前换行、句中断行、中文数字条号、款项边界已有处理 | OCR 增加后，清理还需要处理空格、噪声、分栏、页眉页脚、错字，并用条号序列和外部文本验真 |
| OpenViking | 当前项目已真实接 `0.5.3`，用 BGE-M3、`find` 和 revision scope；OpenViking 新代码另有时间衰减 | 一期可沿用现有连接，增加“编/章/节/条/款/项”的层级 URI和元数据；时间衰减不能代替法律生效期 |
| 时间字段 | API 已经有 `event_date`，但当前排序只按关键词、向量、RRF 和模型重排 | 需要新增时间校验和时间重排，并在响应、trace、前端中展示依据 |
| 民法典版本 | 当前仓库只有 2020 通过、2021-01-01 施行的文本；`effective_from` 仍为空，来源待审 | 2021 以后“当天有效版本”需要补充修订/替代版本；单本 PDF 不能证明后续仍无修改 |
| TimelyRAG | 官方实现公开；四类时间为查询时间、查询事件时间、文档写入时间、文档事件时间，二阶段重排 | 可借鉴时间距离、候选池归一化、因果性和按时间表达能力调整权重；法律场景需要更严格的有效期过滤 |
| 评测数据 | 现有 120 道民法典题由 AI 编撰，全部需人工复核；其中仅少数直接测试时间 | 可以用于开发防回归；正式质量证据还需独立标注或专门的时间版本题集 |

## 为什么选这三项技术

**PaddleOCR**：民法典 PDF 已有文字层，真正价值在于给扫描版、缺字、乱码或未来新法建立可追溯的 OCR 路径。我们会固定模型和版本，保留页面图像、坐标、单字置信度和模型输出，再做法律结构重建。现有原生抽取作为对账基线；相同文本不重复依赖 OCR。

**OpenViking**：检索层继续使用已经验证过的真实 OpenViking，而不是再写一个“仿 OpenViking”的参考实现。结构化索引把民法典目录语义带入检索：编、分编、章、节、条、款、项成为可定位路径，正文哈希、PDF 页码和 OCR 坐标继续保留。目录范围可以提高召回精度，但最终仍用候选内容回答问题。

**Timely RAG**：民法典正文本身只有一次施行日，2020 版还废止了九部旧法。只用“发布时间新”无法处理历史案件、追溯适用、特别规定和修订版本。方案会把查询日期、文档生效期和内容里的时间条件分开，先决定哪些版本有资格作为证据，再按时间接近度、语义相关性和引用结构重排。

## 时间检索怎么工作

1. 用户问一般法律知识时，只使用当前有效版本。
2. 用户描述案件时，必须得到事件发生日；按那天有效的内容找条文。
3. 用户明确询问旧规则、修订前后变化或历史事实时，按问题里的时间窗查询。
4. 如果资料没有足够证据证明某日期有效，系统提示“效力待核验”，不能把不确定资料标为有效。
5. 每个候选同时保存生效起止、写入时间、来源哈希、修订关系和页码。时间只加在已有语义/重排分数上，不把日期相同的错误条文强行排到前面。
6. 先由规则判断硬约束，例如事件日早于施行日，或证据已过期；再用时间接近度排序。这样能避免 TimelyRAG 论文中的“时间接近但已失效”候选在法律场景获得高分。

## 对开发的要求

一期交付包括：PaddleOCR 可复现解析器、数据清洗和 1,260 条逐条校验报告；民法典编章节条结构索引及 OpenViking 入库闭环；法律时间字段、修订关系、时间重排和 API/页面展示；一套能复现的检查与评测协议。所有解析产物、模型身份、失败样本、时间判断和指标都保存下来，方便以后写简历或换 AI 接手。

不要重复重新生成历史资料。现有 2020 文本可作为版本起点；真实现行时间线需要从全国人大法律法规数据库获取并核验来源，或由你提供已获授权的后续修订资料。未核验版本仍可用于开发和 OCR 对比，但不会作为正式“现行法律”发布。

## 验收怎样算通过

第一期不以单个 nDCG 或标签一致率判定成功。必须同时满足：

- OCR：1,260 条全部可追溯，逐条正文与外部同行文本对账；关键字段错误能被检出；异常不静默丢弃。
- 结构：编、章、节、条、款、项关系正确，OpenViking URI 与 Catalog 原文能一一回读。
- 时间：所有参赛版本有可审计有效期；过期内容不能出现在可回答证据中；有效版本命中、过期错误、时间排序和日期解析分别计分。
- 检索：在相同第一轮候选池下，比较有/无 Timely 重排；报告 nDCG、Recall、MRR 和时间有效性指标，不用总体改善掩盖过期错误。
- 回答：引用必须来自同版本原文，回答记录事件日、版本依据、是否需补充事实和效力状态。
- 工程：可安装、可启动、可复现；不依赖本机隐藏状态；模型、数据、源码和测试都有身份记录。

## 推荐默认选择，待你确认

- 版本范围：**直接搭真实民法典时间线**，先完成 2020 版，再接入能核验的后续修订。这样不会把单版本原型误写成历史检索能力。
- 时间基准：**事件发生日优先**；用户没有提供具体案件日期时先追问，一般法律知识问题则按当前版本。
- 正式评测：**时间有效性优先**。先看是否找到当时有效版本，再看总体排序；nDCG、Recall、MRR 作为伴随指标。
- 你提供的资料：后续修订文本可以告诉我存放位置；如果没有，开发会先能从公开法规库核验并保存来源。

方案还有两点需要你决定：民法典是否只限中国大陆、公开库是否只按中国大陆法律处理；以及“当前有效版本”是否允许法律人员复核后才发布。默认建议公共服务只在中国大陆范围内答题，现行效力必须经过来源和内容复核。
