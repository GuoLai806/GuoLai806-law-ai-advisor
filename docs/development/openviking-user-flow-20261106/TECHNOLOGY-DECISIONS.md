# 为什么采用这些技术，以及证据能证明到哪里

本文对应真实 OpenViking 用户流程这一轮。正式300题已完整完成，成绩已写入 [用户版](PLAN-FOR-YOU.md)；接口和执行约束见 [执行版](PLAN-FOR-AI.md)。不能把上一轮精确余弦参考后端的分数当成本轮结果。

## 1. OpenViking负责资料入库和语义检索

采用 OpenViking 0.5.3 独立服务。网页与GET /api/v2/units/{id}查看正文时，读取本地Catalog/SQLite中对应版本的原文；OpenViking原文回读发生在入库验收。每题原文hash回读验证的是产品原文接口与所选证据一致，不能说每次网页原文查看都直接调用OpenViking。5,183篇资料已经实际导入，每篇内容回读后校验SHA256，并确认能在对应scope中被检索到。完整导入920.95秒，独立回读与可见性检查121.49秒；失败的早期导入报告也保留。

原因是用户明确要求用OpenViking，而用户体验测试也必须走实际服务。本轮不是预先算好向量矩阵再替换服务请求。真正验证过的是完整L2单元的导入、向量检索、scope隔离和原文定位；没有把未测试的L0/L1摘要、长文层级检索、OCR或多模态能力写成项目成果。

索引采用`vectors_only`、`parse_mode=no_split`。每个单元独立存放，L2地址为`scope/unit_id/unit_id.md`。该地址来自真实导入后核验，早期猜测目录地址造成的失败已修正。单元版本、正文hash和检索可见性全通过后才能激活版本；结果未知时先查实际状态，不能盲目重放写入。

## 2. 关键词和向量一起找，再用RRF合并

关键词检索使用SQLite FTS5/BM25，向量检索使用OpenViking配BGE-M3（1024维）。两种方法常能补到不同资料：术语和编号适合关键词，表达不同但意思相近适合向量。RRF按照各路排名融合，避免把两种不在同一量纲的分数直接相加。

本轮已从300题真实trace恢复关键词、向量、融合前三种排序，各来源前20名完整，无coverage缺口。nDCG@10分别为0.668898、0.644566、0.704273；最终重排为0.794201。相对BM25差+0.125303（相对18.73%），95%配对区间[0.092150,0.159107]；相对融合差+0.089927，区间[0.061724,0.120235]。这样的对比只能解释检索阶段的贡献；没有为每种检索方案都重新生成答案，不能据此宣称完整问答也提高相同幅度。

BGE-M3来自前一轮冻结验证的模型选择，延续已验证的语料索引，避免在正式测试中途更换向量空间。这里不声称它是当前最强embedding。公开模型表里的BGE-M3原版SciFact nDCG@10为0.64366，NV-Embed-v2为0.80111；本项目增加了关键词融合和重排，比较时必须说明系统组成不同。

## 3. Qwen重排的质量与速度取舍

最终同配置对照各32题，均保留1题失败。Qwen3-Reranker-4B与BGE-reranker-v2-m3的结果如下，失败都在分母中：

| 指标 | Qwen | BGE |
| --- | ---: | ---: |
| 三类标签一致率 | 68.75% | 68.75% |
| 三类macroF1 | 0.579638 | 0.574074 |
| 引用文档与标签F1 | 0.513761 | 0.479167 |
| 检索nDCG@10 | 0.835023 | 0.803544 |
| Recall@20 | 0.937500 | 0.937500 |
| 用户等待中位数 | 39.815秒 | 17.576秒 |
| 重排阶段中位数 | 19.641秒 | 1.126秒 |

按照事先确定的顺序：先比较macroF1，再比较引用文档与标签F1，再看nDCG，最后看等待时间，选择Qwen、batch8、MPS float16。此前跑过的更高分候选不替换最终对照。选择是为了本轮偏质量的目标，不代表速度最佳。

事后配对重采样的95%差异区间都跨0：nDCG差值0.031479，区间[-0.001965,0.079202]；macroF1差值0.005564，区间[-0.119872,0.129501]；引用文档与标签F1差值0.034595，区间[-0.079199,0.142780]。32题不足以证明稳定领先。模型权重磁盘字节约8.044GB对2.271GB，不能把磁盘大小当运行内存。

Qwen和BGE的原始重排分数不是统一概率。本轮沿用的生成门槛0，在正式测试中17题因门槛仅展示证据，未生成可交付答案。运行途中不降低门槛。下一版应只用开发集分别标定门槛，比较无关资料误放行、正确资料被拒绝、整体质量和流程完成率；不能为了完成率直接关闭门槛。

## 4. 回答模型与证据数量

正式配置为`deepseek-v4-pro`，thinking enabled、effort low，最多4条完整证据、6,000证据token；模型窗口配置32,768、固定包装预留512、输出预留8,192，第一次请求最多60秒。科学论断提示词要求首行明确给出支持、反驳或证据不足，再解释并引用。

开发集经历了Flash/Pro、思考设置、证据数量、输出空间和提示词的多次试验，全部报告保留。最早Flash候选32题有13次失败，标签一致率46.875%；最终Qwen配置31次完成、一致率68.75%。这些试验同时改变了多个条件并修复了代码，不能把全部提升单独归因于Pro、某一句提示词或4条证据。

采用4条完整证据，是为了控制本机重排后的生成上下文和等待，同时保留完整依据。开发集25道支持/反驳题，在被检查的Qwen排序中，前4条标注文献覆盖为1.0，前8条没有新增覆盖；其原报告hash和逐题数据保存在`validation-evidence-coverage.json`。这只是排名覆盖，排除没有gold文献的7道证据不足题，不能替代实际预算后的证据或答案评分。它是开发集试验的联合配置，不是证明了4永远优于8。正式分析另报预算后所选证据覆盖（生成题才实际送入模型），不能用检索前20的Recall替代。

在最终Qwen验证中，真正选入证据的标注文献完整覆盖为24/25道支持或反驳题；其中2道在覆盖完整且没有流程错误时仍判错，另有1道生成失败。排名覆盖不能代替最终答案质量。最终两组的7道证据不足题都只判对1道，该类别F1均为0.2222。这是高精度目标的重要短板：找到相关资料后，模型仍可能给出过于肯定的判定。不能把重排分数高或引用编号有效当成结论可靠；正式结果必须单列该类别。

预算使用已固定的官方tokenizer，按完整单元取舍，不截断段落制造貌似完整的依据。云模型是别名，保存实际返回model、fingerprint和日期；没有固定云端权重，无法承诺逐字重现。

## 5. 只对完全空回答重试一次

开发中观察到思考调用占满预算但没有输出正文的失败。允许第一次完全没有正文且属于明确空输出类失败时，用同模型、同一批证据关闭思考再试一次，最多45秒、2,048输出token。没有第三次。

已有部分回答、连接错误、非法引用、内容限制、用户取消不能触发这种重试。这样做是针对空输出故障，不是挑两次里答案更好的一次。最终等待包含两次，按调用分别保存用量；缺报用量仍是未知，不能填0。

## 6. 引用、原文和会话各自检查

引用检查确保编号指向实际给出的证据；原文回读确保仍能打开同版本、同hash资料；会话回读确保完成答案已保存、截断草稿没有冒充完成。三项检查能够证明流程和来源一致。

它们无法证明每句话在语义上都受到文献支持。SciFact标准标签另外计分；引用文档与标签F1是本项目定义的指标，不是官方句子rationale榜单。没有专家核验时，不会把来自未标注文献的不同判断宣布为标准答案错误。

## 7. 为什么还要锁版本、留失败和做独立复核

配置原字节hash、源码、模型文件、tokenizer、语料和scope都记录下来。正式300题只能使用已选配置。TREC独立复核检索分数，逐题重采样给出区间；公开材料保留全部失败、排名、标签、耗时和报告用量，正文和凭据留本机。

这样面试时可以解释每个数字从哪里来，以及边界是什么。审计通过说明数据和过程能对上，不能解释成所有题目正确。共享M5 Pro桌面、单客户端串行、云接口等待这些条件必须披露，不能包装成生产吞吐或专用服务器延迟。

## 8. 下一版按什么证据做决定

先标定重排门槛并检查错误切片，再评估质量与延迟的取舍。新的质量版本需冻结新的开发选择，并用新的、未参与调整的评测协议验收，完整保留本轮。扩展到通用RAG，还需要不同领域、中文、长文与无法回答问题的数据集；科学摘要这一个测试不能证明所有场景。

要写“前沿”，需与可复现的强基线在同一输入、同一任务定义、同一评分和失败口径下比较，并覆盖完整答案、语义引用和等待。公开embedding表只可作检索参照。要优化线上体验，还需单独做并发和资源测试，不能直接从本机这一次串行运行估算容量。

## 正式結果对下一轮的约束

188道有gold文献的题里172道最终证据完整覆盖，但其中19道无流程错误仍判错，9道评分失败。NEI为58/112正确；引用doc+label precision=.410714、recall=.770335、F1=.535774。证明检索改善不能替代判别和引用质量改善，优先做开发集门槛标定与无法回答切片，再冻结新协议。不能用本轮正式错题调参后覆写成绩。

正式共有10题空回答重试、293次生成尝试、269题usage可用、259题attempt用量齐全。共享桌面本轮实际合盖睡眠约4小时6分，原monotonic延迟不能证明连续用户日历等待或线上性能；完整数据与时钟依据见[RESULTS.md](RESULTS.md)。后续非流式/chat已修attempt累计和缺报状态，10专项和180回归通过，正式SSE未改。
