# 评测怎么跑，数字分别说明什么

本文解释本轮真实 OpenViking 评测的固定规则。最终结果与开发决定已放在 [用户版](PLAN-FOR-YOU.md) 和 [执行版](PLAN-FOR-AI.md)。

原文查看的分工：OpenViking参与实际入库、语义检索及入库回读验收；用户查看原文时，产品接口读取本地Catalog/SQLite的同版本正文并校验hash。每题原文回读不是再次向OpenViking取正文。

## 测的是哪条路

全部5,183篇科学资料实际写入OpenViking 0.5.3，每个完整单元回读内容并核对SHA256，确认能够在自身scope下检索到，再激活语料版本。用户提交问题后，服务请求真实OpenViking，结合SQLite FTS5关键词召回，通过RRF合并，交给重排模型，再按生成模型的token预算挑选证据。实际云模型返回SSE答案，服务检查引用编号，完成答案存入会话。评测客户端随后读回每条证据原文并核对内容，再读回完成答案。

不存在把预先算好的相似度矩阵冒充OpenViking请求的步骤。每题保留实际dense_backend、dense_scope、候选来源、重排得分、证据选择与阶段耗时。此次是单个问题到答案和原文的完整路径，另做浏览器实操。它不是生产并发压力测试，也不是多个追问之间的上下文理解测试。

## 先定配置，再跑正式题

验证集固定为SciFact train中32题，选择方式和ID在冻结manifest中。全部候选保留，技术修复前的失败报告也保留。最终候选用相同的代码和生成配置，分别比较BGE与Qwen重排，先要求运行完整、源码和运行身份一致、没有已知流程缺陷，再比较三类macroF1、引用文档与标签F1、检索质量，最后以延迟决胜；用量单列报告。32题只提供选型信号，不能证明某个配置稳定领先。

选定配置记录原字节配置SHA256、验证报告SHA256、源码、模型、tokenizer和索引身份。正式300题必须匹配该配置。正式题跑完后不会按结果改提示词、过滤文献、删除失败、替换标准答案或挑选同配置最好的一次。

BEIR test300用于检索评分；其ID与文本对应SciFact公开dev300，后者提供支持、反驳、证据不足标签。这是公开开发标注，不是隐藏榜单测试。该300题曾用于旧参考检索后端，因此不能宣称整个项目从未见过这些题。

## 六种数字分开看

| 数字 | 说明 | 不能推出的结论 |
| --- | --- | --- |
| nDCG@10、MRR@10 | 前面是否排着标注的相关文献 | 最终答案一定正确 |
| Recall@20 | 候选前20找回多少标注相关文献 | 送入模型的4条也全部覆盖 |
| 最终证据覆盖 | 预算后所选证据覆盖（生成题才实际送入模型）多少相关文献 | 模型理解并正确使用了证据 |
| 标签一致率、macroF1 | 输出与既有三类人工标注的一致程度 | 通用问答事实准确率或官方SciFact榜单分数 |
| 引用文档与标签P/R/F1 | 引用文档是否在标注文献内，同时判定正确 | 逐句语义引用已经人工核验 |
| 流程完成、耗时、用量 | 服务是否交付完整答案、能否回读原文和会话，以及实际等待与报告用量 | 高并发容量、云账单或整体答案质量 |

服务只检查引用ID存在，不自动证明每句话受到文献支持。我们没有预测官方句子rationale，因此引用文档与标签F1不能与官方abstract/sentence评分混用。相关标注来自原问题引用文献，并没有穷尽全库每篇资料的所有事实；没有专家复核时，其他文献看似支持也仍照原gold计分，不宣布标注错了。

## 失败与重试怎么算

超时、流断开、截断、非法引用、检索降级、分类格式错误和会话回读失败均保存。分类计分把失败记为INVALID，仍在分母中。分类格式无效但实际答案完成时，继续原文和会话回读，另记真实流程完成；不能把这两种指标混成一个成功率。

只有第一次完全没有输出且超时、无内容截断或缺少完成标记时，才允许复用同一批证据、同模型关闭思考，再尝试一次。第一次最多60秒，第二次45秒、2,048输出token，没有第三次。已有部分答案、引用错误、限制终止、取消或检索降级不这样重试。每次调用、重试原因和等待都保留；最终等待包含两次。模型未报告首次用量时标usage_complete=false，已知用量之和不能当全部费用。

## 统计和外部参照

用NIST trec_eval v9.0.8独立复核逐题和总体检索评分，容许四位小数输出的舍入差异。置信区间使用按query重采样10,000次，固定seed20261106，95%百分位区间；它反映这批数据的抽样不确定性，同文献问题可能相关，不能直接作外部系统显著性检验。

最终表格耗时采用NumPy线性插值p50/p95，并保留runner原始离散分位数。首字是第一个可见答案字符，不含隐藏思考。用户总等待从POST开始到原文及会话回读完成。所有失败题仍保留已有等待，完成流才有服务端总耗时。

外部资料来自固定commit的官方embeddings-benchmark/results仓库。调查明列38个模型配置，其中14份原版SciFact同task/revision结果可作检索参照；不同任务版本、翻译集、Nano和LMEB不拼成同榜。外部报告硬件、检索策略、模型和软件版本不同，且不包含本项目的生成、引用和会话流程，因此即使检索接近高分模型，也不能写全流程SOTA。

## 哪些材料公开

公开全部逐题标签、候选排名、失败、耗时、用量、源码与数据hash、配置和统计分析，保留原始报告与脱敏副本各自的SHA256。原始SSE、回答全文、资料正文、模型权重、云凭据和私人路径留在本机，不推到公开仓库。脱敏不会删除失败题或改变数值。审计通过只证明证据一致，不能解释为300道题全部答对。

## 本轮计时的实际限制

正式UTC跨度25,073秒，逐题单调时钟之和10,378.623392秒；macOS电源日志实际Sleep交集14,756秒。正式Python3.12.13的monotonic实现为mach_absolute_time，睡眠期间与日历推进不同。无逐题UTC，不能把睡眠分摊到每题或修正p50/p95。原始分位数仅作为该运行时秒表记录保留，不证明持续唤醒的真实用户日历等待、线上延迟或QPS。ConnectError等根因未被证明。时钟与电源匿名审计见[evidence/host-timing-audit-v1.json](evidence/host-timing-audit-v1.json)。下一轮同时留UTC/wall与monotonic并约束主机唤醒条件。

原始一致性审计在冻结7231源码、后续API修复前完成27项。最终交付HEAD中普通/chat新增用量累计和metadata；正式SSE未修改。重新做历史raw审计必须在冻结checkout中使用交付audit工具，不能取消source_hash检查。正式结果见[RESULTS.md](RESULTS.md)。
