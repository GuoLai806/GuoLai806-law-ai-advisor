# 简历可用句子与面试解释

本轮实测完成后可以写下面的项目表述。项目历史日期保留真实日期，另注明2026.11完成OpenViking重构和评测；原Word没有覆盖。结果和限制分别见[用户版](PLAN-FOR-YOU.md)、[完整结果](RESULTS.md)，后续实施依据见[AI版](PLAN-FOR-AI.md)。

## 可直接使用的三条

**通用证据 RAG 检索与问答系统（由法律 RAG 重构）｜核心开发**

- 将早期法律RAG重构为通用证据服务，基于OpenViking实现版本化资料入库、来源定位和正文hash校验，结合BM25、BGE-M3向量检索、RRF融合及Qwen重排，实现完整证据预算、真实SSE回答、引用编号检查和原文回读。
- 在SciFact 5,183篇语料、全量300题检索评测中，nDCG@10达到0.7942、Recall@20达到93.59%；基于同题实际检索轨迹，最终排名相对BM25的nDCG@10提升18.73%，配对重采样95%差异区间为[0.0922, 0.1591]。
- 建立从真实OpenViking检索、云模型生成到原文及会话回读的全流程评测，固定开发选择与正式配置、源码和模型身份，保留逐题排名、标签、失败及用量；使用TREC工具复核检索指标，并以独立审计检查原始流与报告一致性。

第二条中的提升只指检索阶段。公开表中有同数据集的高分embedding可作参照，但方法、模型和硬件不同，简历无需加“领先业界”。第三条可以说明拥有评测和错误分析能力，不能暗示全部题目正确。

## 面试时怎样把结果讲完整

如果被问“最终答得怎么样”，应直接回答：标签一致率70.67%，三类macroF1为0.7396，自定义引用文档与标签F1为0.5358，完整流程完成269/300。31次失败也在分母里，其中17次只给资料、14次生成错误。证据不足题58/112正确，说明相关资料检索后是否足以支持结论仍是短板。这不是通用事实准确率，也不是官方SciFact句子rationale榜单评分。

如果被问“为什么Qwen”，解释固定32题同配置比较和质量优先规则；质量差异区间跨0，而等待中位39.8秒对17.6秒，当前还没有证明小幅收益值得速度代价。这个诚实的取舍比把模型名字列满更能说明技术判断。

如果被问“OpenViking用了哪里”，说明资料实际存入0.5.3服务，每篇回读和检索可见性检查，所有正式题实际find并锁scope，输出原文ID和hash可追踪。本轮完整L2原文，没有验收L0/L1摘要、复杂PDF/OCR或长文层级能力。不要把框架自带功能都写成本项目已验证成果。

如果被问“速度和成本”，说明正式运行期间主机发生约4小时6分睡眠，所以原始秒表p50/p95不能当真实日历用户等待或生产延迟；已知608961 tokens有缺报，不能当总费用。要测速度需持续唤醒机器并逐题记录日历时间，不能沿用“首字低于500ms”或“成本降低90%”。

## 原有措辞如何处理

| 原有方向 | 本轮可以怎样改 | 理由 |
| --- | --- | --- |
| 法律检索、高精度问答 | 通用证据RAG；有可选法律profile | 正式质量来自英文科学资料，没有专业法律人工验收 |
| 回答准确率95% | 检索Recall@20=93.59%、nDCG@10=.7942 | 召回不是回答正确率；本轮标签一致率70.67% |
| LoRA微调效果95% | 只有保留独立训练/测试资产时另写 | 本轮没有重新证明训练效果，不借RAG数字证明微调 |
| SSE首字低于500ms | 真实模型SSE、完成标记检查、停止撤回 | 实测不是500ms，跨睡眠延迟还存在测量限制 |
| 成本下降90%、高并发 | 已报告attempt用量追踪、会话绑定与服务化 | 没有同任务账单基线或生产压测 |
| 引用可靠或无幻觉 | 引用ID结构校验、版本原文回读；标签与文档质量另测 | 原文可追踪不等于逐句语义支持 |
| 全流程SOTA | 同SciFact检索数值接近部分公开高分配置 | 未对完整回答强基线做同口径比较，数据集范围有限 |

这些规则针对本轮能证明的成果。其他历史训练或企业项目若有独立材料，可以按其真实范围保留；不应把本轮成果倒填到旧日期。下一版应优先解决证据不足判断、门槛误拒绝、引用精度和可靠性，再冻结新的评测协议验收。执行顺序见AI版。
