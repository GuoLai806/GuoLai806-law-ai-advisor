# 这一轮先把 RAG 做好

[给开发 Agent 的同一份决定](PLAN-FOR-AI.md)

这轮先做两件事：让 OpenViking 的网络连接可以连续使用；增加“先看资料”，看摘要预览后能打开同版本完整原文。保留现有真实 OpenViking、关键词加语义检索、合并排序和 Qwen 重排。正式回答仍使用完整段落，不能拿截断预览充当依据。

当前版本每次检索都会重新建连接。这次会明确谁负责关闭连接，服务退出先等已有请求结束，取消一条请求不会影响其他请求。复用的收益必须在真实 OpenViking 上测；本机连接本来就很快，最终回答不一定变快。

“先看资料”是可选入口，原来的直接问答继续可用。预览会清楚标明是否截断，并能回到对应版本的原文。它减少展示的数据量，不绕过完整正文重排或回答预算，不承诺降低所有等待时间。

先用已约定的 6 题检查，再固定 30 题比较，保留失败和原始记录；另做长文、取消、退出和跨版本场景。比较时两组均使用已验证的摘录检查模式；产品默认文本模式继续保留。分开报告网络阶段、展示大小、回答质量和总等待，不把小样本写成行业领先。

顺序是实现、相关测试、独立评审与修复、构建安装、走真实网页和问答入口、整理数据、推送 GitHub 并核实。只推公开独立实现和脱敏材料。旧安装和索引保留，出现问题可关闭探索入口或切回逐次连接。

其他待办：GCode/Pi 差距优化、CU 移植、SuperAgent 集成、MyAgent 融合、简历更新；等你以后确定方案再做。RAG 的来源/类型/时间过滤和后台入库队列另列后续，避免一次捆绑太多改变无法解释数据。

代码、439项回归、独立评审、构建安装和两组真实30题数据已经完成。结果是：连接find中位24.7→21.3ms；两组都答对22/30、完整流程29/30；探索总等待中位53.5秒，直接40.6秒。预览作为可选浏览入口保留，不能写成完整回答提速或行业前沿。引用文档标签F1 .6667→.7143，但同一回答配置下的输出差异不证明预览改善语义质量。

[完整结果](RESULTS.md)说明失败、用量、统计范围和原始记录；[选型理由](TECHNOLOGY-DECISIONS.md)解释为何保留这些实现。网页交互验收也已完成：能看截短预览、打开完整原文、得到带核验引用的回答，停止和修改问题会取消旧请求。当前已准备好交给你体验；GitHub 同步在最后归档步骤核实，用户本人最终验收仍待确认。

计时还有一项重要限制：直接组一题的日历等待约19.3分钟，单调时钟约2分钟，差约17.3分钟；原因未知，记录保留且没有扣除。其他分位数不能遮住这条最大等待，两组速度差不能作为稳定提速证明。

本机体验入口是 http://127.0.0.1:19447/ ，演示令牌是 `loopback-demo`，只在这台机器的本地接口使用。当前展示的是已约定的可选摘录核验模式，英文 SciFact 示例；它不改变产品默认文本模式，也不是中文/法律质量验收。服务和旧索引保留，数据库已做一致备份并通过完整性检查。停止回答时参考资料区有一句旧的“正在查找”提示，主状态已明确停止、没有旧答案覆盖；这是不影响本轮功能的界面小问题，列为后续。
