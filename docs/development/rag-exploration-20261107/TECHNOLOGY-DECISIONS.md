# 为什么这样改

[用户版](PLAN-FOR-YOU.md) · [执行版](PLAN-FOR-AI.md)

## 连接复用：改资源使用，不动排序

原实现一次find新建一个httpx.AsyncClient；两步入库在同次ingest里共用临时client。现在adapter默认持有连接池，服务和CLI负责关闭。用已有httpx而不引入另一套连接层，因为检索、鉴权、timeout和测试都已依赖它，变化更容易隔离。构造器仍支持transport，增加client/owns_client/reuse_client。外部client默认借用，显式转交才关闭；自建一定由adapter负责，矛盾配置拒绝。禁止环境代理和重定向，逐请求明确headers和timeout。

关闭时先拒绝新请求，再排空已接受的find/ingest。取消一个请求不关闭整个池；取消等待关闭的调用者也不打断真正的关闭。逐次模式仍可用于回退及同实现对照。索引工具在同一个asyncio.run里操作和关闭；日志或回调出错时先取消并收回兄弟任务，防止数据库已关闭还有任务访问。未知入库结果保留delivery_unknown，不重放写入。

真实OpenViking0.5.3、同5183篇SciFact索引、同30题、交替AB/BA、不重试：60请求成功、结果30/30逐项完全相等。逐次/复用的find中位24.7279/21.3095ms，配对差中位-3.282ms，26/30复用更快；p95 40.754/26.325ms。两次预热单列，暖本机loopback网络，无TLS。它支持保留复用，但不证明远端网络、并发吞吐、完整回答显著加速。

## 预览：浏览入口与生成依据分开

增加/api/v2/explore，是因为用户先浏览资料与要求生成答案是不同动作。API仍用完整候选正文重排，但探索不应用生成提示预算，所以超出回答预算的完整段落仍可被发现。输出320字符预览，明确截断和是否还有更多内容；带段落/全文hash、定位、part_no和同revision原文指针。返回独立exploration_only类型，无evidence/budget，不可直接传给生成逻辑。现有retrieve/chat/stream的完整证据与预算门槛继续有效。

使用已有Pydantic验证与标准JSON，避免新依赖。320字符只是明确的界面默认值，模块支持1..2000；没有按正式题分数寻优。hash在截断前核对，打开原文时客户端核对完整段落和全文hash。网页把查询和版本关联，问题改变时取消旧探索；旧原文返回也不能覆盖新状态。所有标题、预览、正文使用textContent。

这不实现跨轮缓存、查询改写或摘要重写。探索后点击回答会再次真实检索和重排，固定探索版本；如果已激活其他版本，回答明确拒绝旧版本而不悄悄换资料。保持独立路径让质量边界容易审计，代价是额外一次检索和原文读取；是否变慢由正式数据回答。

## 同配置对照，保留默认方式

产品默认仍text + reranker_threshold。正式两组都使用已有可选grounded_json + grounded_evidence，只改顶层user_flow_strategy：direct或explore_then_answer；检索、模型、提示、预算和完整证据配置完全相同。选择文件在发出正式请求前绑定开发6题、两套配置、同30题、源码、工具hash和正式输出路径，拒绝篡改、覆盖或额外配置差异。

grounded模式核对引用摘录字面存在，不是独立证明结论正确。分类正确率和引用文档标签F1使用公开SciFact标签；不把它们叫官方排行榜分数或所有领域事实正确率。30题曾经公开使用、每类10题；开发6来自train，与30不重叠。6题开发4题正确、6条流程完成，只证明接口可运行，不选最佳参数。

## 时间、用量和公开记录

从用户动作开始计时。探索组包括预览、打开首条完整原文、实际SSE回答、答案引用原文和会话回读；直接组从直接问答开始。旧stream_total/first_answer字段在探索组也包含前置等待，report显式说明；service_total仅回答服务请求。双时钟记录UTC/ns和单调时间，审计按探索样本→SSE→结束独立重建。失败没启动SSE时stream/first为未知，不伪造0或缺失墙钟。

保存实际HTTP JSON body字节数，与重编码的evidence_ready JSON payload大小分开；后者不等于wire字节。正式runner为了核验配置开启trace，网页默认不带trace，其大小不能混着比较。探索额外请求不抵扣完整回答证据，不能把预览小写成总流量省。

原始报告/journal/SSE/预览/原文/失败/usage在本机保存，公开只传数字、hash、版本及必要脱敏资料。未报usage是未知，失败保持分母。首次构建的缺setuptools日志保留；model环境构建成功。wheel隔离安装，依赖通过.pth明确复用已有模型环境，不冒称全新依赖环境。

## 对企业参考的使用边界

上一轮只读研究未证明企业adapter的完整质量或性能更好；它的预览型记忆入口与我们的版本证据问答目标不同。本轮独立实现共享连接和探索分离，保留个人项目已有排序与完整正文；没有复制企业源码，也没有把未运行的企业部署当基线。详细依据留在[历史对照](../bvio-superagent-research-20261107/RAG-COMPARISON.md)。
