# 实际结果：连接复用有小收益，探索增加浏览步骤

[用户版](PLAN-FOR-YOU.md) · [执行版](PLAN-FOR-AI.md) · [选型理由](TECHNOLOGY-DECISIONS.md) · [复现](REPRODUCTION.md)

## 结论

保留连接复用和可选“先看资料”。连接复用只让本机find阶段少几毫秒；探索没有改善这30题的正确数量，反而增加总等待。正式回答继续使用完整证据，产品默认text不改变。数据不足以证明业界前沿。

## C1：同30题、实际OpenViking网络

实际OpenViking0.5.3、同5183篇SciFact、BGE-M3、warm loopback；交替AB/BA、串行、无重试，2条预热单列。60请求全部成功，30/30pair完整find结果hash相同。find中位逐次24.7279ms、复用21.3095ms，p95 40.7536/26.3249ms。配对差中位-3.282ms、均值-6.256ms，26/30复用更快。实际TCP机制测试也确认复用两次仅接受1条连接、逐次2条。

证据见[evidence/connections-v1.json](evidence/connections-v1.json)：完整每次失败/时间/结果hash保留，原始find rows本机保存。该组件快照与正式用户路径快照的runner文件存在差异，OpenViking adapter本体hash相同；不能把组件结果说成完整RAG提速、远端TLS收益或并发吞吐。

探索预览P50 18.49s，P95 29.90s；打开首条原文的两个观察点之差P50 2.36ms，含客户端处理，不是纯网络。所有预览最多320字符/项，4项，完整段落/全文hash和同版本指针保留。

正式trace开启时预览HTTP JSON body P50 25776bytes，30题总773,030bytes；额外首条原文body共131,909bytes。完整答案的evidence_ready compact JSON重编码P50约31,378bytes，仍然发送，没有被预览替代。不同字节口径不能相加冒充wire总量，也不能把预览较小写成总流量省。网页默认无trace，另做功能检查，不混到正式字节统计。
